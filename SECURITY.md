# Security policy

## Supported versions

Security fixes are provided for the latest published release. If a report
affects an older release, first confirm whether the problem is still present in
the latest version when it is safe to do so.

## Reporting a vulnerability

Do not disclose a suspected vulnerability, credential or authenticated Solesta
response in a public issue. Use GitHub's private vulnerability-reporting option
on the repository's **Security** tab once that option is enabled.

Include only the minimum information needed to reproduce the issue. Redact
account details, cookies, tokens, addresses, system identifiers, private network
addresses and Home Assistant storage data.

Ordinary bugs and feature requests can use the public issue templates.

See [Privacy and security](docs/privacy-and-security.md) for the data handled by
the integration and the information that must not be shared publicly.

Maintainers should also apply the controls in
[Maintainer security](docs/maintainer-security.md) when the GitHub repository is
created.
